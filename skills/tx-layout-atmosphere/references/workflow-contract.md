# 踏星｜跨程序镜头交付流程 v1

入口为项目 `AGENTS.md` 和 [SKILL.md](../SKILL.md)。这套约定与宿主和出图模型无关；优先复用当前已核对的镜头、有效区、参考和历史版本。需要迁移时复制整个技能目录，不要只复制提示词。

## 先选任务

| 用户要求 | 默认结果 |
|---|---|
| 按镜号／剧情找特效参考 | 独立动态 GIF + 内嵌同批 GIF 的原生 PureRef + 可追溯原片说明，见 [参考交付](pureref-vfx-board.md)。未要求出图，不生成新成图。 |
| 按镜号／Layout 出图 | 每镜一张 4K PNG，另保存原帧、简报、原始渲染和验收记录。 |
| 同镜返修、批注改图 | 指定版本是唯一编辑底图；批注只作区域／方向说明，不进成片。交新版本，原版和未点名镜头保留。 |
| 同步特效设计 | 沿同一镜头流程出图；需要时附简洁设计说明，记录形态、时序、灯光互动和制作建议。未实测不写成引擎实现。 |
| 已提供剧本但缺 Layout | 参考板可继续，Layout 标待补；需要锁构图的出图待补原帧，不合成假 Layout。 |

## 同一条工作线

1. **定镜号和阶段。** 将 `3-6-69` 解析为 `Ep003_sc006_069`，保留 `a/b` 等版本尾缀。按项目索引找到单镜 Layout，必要时核前后镜；剧本/StoryBook 定时段和因果，Layout 定机位、动作和遮挡。优先用现有已验证原帧；如需重新抽帧，从原视频按一基帧号取 PNG。只剥离有证据的预览框／时间码，不裁有效画面。把集／场／镜、源文件、帧号或秒数、有效区记入工作资料。
2. **按实际可见项配参考。** 场景、角色、服装和道具优先匹配本镜 Shading，缺合适 Shading 才回退到设计图；因设计图偏手绘易影响整体写实 CG 画风，使用设计图时仅借其光影层次与氛围情绪，排除手绘笔触与画风；成图用光不照抄 Shading 展示光。连续镜先锁主光动机、时间、效果色阶与衰减；已确认样板只迁移明确的用光或材质判断。没有审批证据的参考只标候选。
3. **有实质特效才找动态。** 拆蓄力、释放、命中和余波，按同阶段、规模、方向、受光和环境反馈筛片；实际核原片、记起止秒、选可用高清关键帧。纯表演／普通氛围不搜库。出图只传入确实要借用的帧，不拿 GIF、整板截图、占位色或其他角色当底图。若用户只要参考，走 GIF/PureRef 分支，到这里不启动出图。
4. **整理简报再执行。** 新镜的底图是有效 Layout；返修的底图是被选版本的干净成图。逐张标用途和排除项；明确画面焦点、光源、亮暗与受光对象、特效起点和流向、与前后镜的区别。保存 JSON 并用下方命令检查，然后调用 [适配器](render-adapters.md)。带批注的图可辅助定位，但不作为无批注成图的替代底图。工具无匹配能力时交接简报、提示词、底图与参考，状态「待出图」。
5. **对照实图后交付。** 检查构图四边、机位、角色位置／身份／姿势、场景及未修改区；再验阶段、动势、光源、暗面、材质和前后景。失败只纠正相关项，不把尺寸通过当成画面通过。合格后保留原始成图，用 `publish` 输出 3840 像素宽 PNG 和 `.qa.json`。等比放大保留全幅；不得用裁切、填边或拉伸伪造画幅匹配。没有实际执行时不登记成片或审批。

### 同步特效设计与连续镜

- 用户指定的模式优先；严格跟已有资产或预算用 Production；明确自由探索用 Concept；匹配已批准参考用 Style Match；需要设计但未指定模式，默认 Hybrid（先让画面成立，再说明可做层）。任何模式都不自动放开机位、人物、构图或场景。
- 先锁一条因果链：**发射锚点 → 主形与主流向 → 受击或环境后果 → 衰减**。再选择本镜实际需要的层，例如火核／火体／烟／余烬；分主次与透叠，不给每个招式套同样的光环。把层的颜色、明暗、方向、距离及人物／地面受光写进简报。
- 同招相邻镜共享设定，但按阶段改变规模、亮度和颗粒；例如 3-6-35 的紧凑旋风球到 3-6-37 才成巨型风柱，3-6-64 以掌心蓄势，3-6-69 才把火浪铺到街面。首镜出图核对后，可把它作为后一镜的连续性参考，不复制首镜构图；用户只点名改一镜时不自动改邻镜。
- 有制作要求时，建议以 Niagara 管发射点、条带和次粒子，Houdini/体积或 flipbook 管烟火流体，灯光/合成管局部溢光与遮挡；按本镜选择，不把建议写成已实现。用户要视频或动态关键帧时按同一镜头阶段另做，静帧不称已验证动态。

## 镜头简报与交接

每镜保存 UTF-8 JSON。路径可用绝对路径，也可相对于该 JSON。最小交接件是**简报 + 底图 + 简报中实际引用的本地图 + 已核对的来源/帧号**。未出图的资料包不用填虚构的成图或渲染器。以下演示字段，具体内容应换成已核对的本镜数据：

```json
{
  "shot": "Ep003_sc006_069",
  "mode": "edit",
  "plate": "base_069.png",
  "beat": "俯拍；炎火掌命中金陵街面，已进入爆发峰值。",
  "change": "火流从人物两侧卷向掌心，背景爆点形成更厚的贴地火浪。",
  "locks": {
    "camera": "原俯拍、景别与透视不动",
    "frame": "原图有效比例与四边全保留",
    "characters": "格兰妮位置、大小、手势、双马尾和服装不动",
    "scene": "保留街道方向、落点、废墟位置",
    "other": "只改火流、爆炸和由它们产生的局部反光"
  },
  "lighting": "落点橙金热核为主光；照亮迎火侧，其他区域留冷暗。",
  "references": [
    {"file": "release_keyframe.png", "role": "vfx_frame", "source": "efx_0570｜原视频位置或原始链接", "at_seconds": 0.62, "borrow": "俯视径向爆裂", "exclude": "金色全局曝光、参考角色与机位"}
  ],
  "prompt": "填入完整实际出图提示词：底图、参考分工、只改项、画幅和项目画质要求。"
}
```

新镜将 `mode` 设为 `new`，`plate` 指向 Layout 有效原帧。纯氛围允许 `references: []`；有角色或场景资产时可列 `character`、`scene`、`lighting` 等用途，每张都有 `borrow` 和 `exclude`。附加 `source_layout`、`layout_frame`、`storybook_at_seconds`、`script_beat`、`approved_sample` 时填实际证据，不填猜测。不同程序可保留自身模型、参数或 seed，但不据此承诺不同工具出图像素一致。

## 可复跑命令

从工作区运行。依赖 Python 3.11+、Pillow、FFmpeg（或 `imageio-ffmpeg`）。PureRef 2.x 仅参考板分支需要。下面以 3-6-69 为例：`237 99 1575 660` 是本例已核的预览有效区，不得机械复制到其他镜头。

```powershell
$tool = ".agents/skills/tx-layout-atmosphere/scripts/shot_delivery.py"
python -X utf8 $tool frame --source "<单镜原片>" --frame 27 --active-rect 237 99 1575 660 --boundary-evidence "核对预览框四边，仅排除黑框和时间码" --out "work/shot/plate_069.png"
python -X utf8 $tool check-brief --brief "work/shot/brief_069.json"
# 在所选适配器中，实际传入简报、底图和所列参考；保存原始结果并目视复核
python -X utf8 $tool publish --brief "work/shot/brief_069.json" --raw "work/shot/raw_069.png" --renderer "<实际工具>" --review "对照原底图：四边、机位、人物、街景和只改项已检查" --out "output/EP003_sc006_069_DarkFlame_v03_4K.png"
```

无预览框时省略 `--active-rect` 和 `--boundary-evidence`。脚本不会从生图结果自动裁画面；只允许原生整数像素取整带来的 4K 高度差（最多 2px），仍按原始成图比例缩放。黑边检测只作保守拦截，真实暗边如误报，先目视确认并用 `--edge-evidence` 留痕，不用于放行实质黑边。重新打开最终 PNG 检查，用户回复只交可点击路径、实际分辨率与核心变化；中间材料和记录保留在项目中。
