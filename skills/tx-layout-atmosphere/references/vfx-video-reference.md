# 踏星｜出图前的真实特效视频参考

这里定义选源和选帧。用户要求找参考给他看时，再按 [GIF + PureRef 交付](pureref-vfx-board.md) 输出实物；仅为出图内部采样时不必出板。

## 选源与选帧

1. 从目标 Layout 原帧及前后切点确认本拍是蓄力、释放、擦身／命中、余波还是纯反应。剧本和 StoryBook 核定招式与因果；Layout 占位只证明出现位置、屏幕方向、范围和节拍，不直接定红蓝色、光强或效果材质。
2. 读 `AI/.vfx/style-references.json` 和对应招式设计。用户指定或已确认的参考优先；需要和 UE 一致时，先找并核对同招式、同版本、同阶段的项目 UE 预览。其他项目片段或效果库素材标为候选；LY 编号和文件夹名不等于批准。只有匹配动作和效果层的参考才进入出图。
3. 搜之前先从前因和后果定出本次招式的威力、目标尺度、关键后果和发光优先级；按实际阶段筛相同量级、方向、介质与受光的素材。强发光且用户／镜头设定指定特效为主光时，检索要包含能照亮人物或地形的候选，出图压低竞争环境光；别只找颜色或形状相似的小效果，也别在离手镜提前画命中。踏星有明确设定的镜头，先读[项目镜头设定](taxing-project.md#ep003-sc005042050-双倍波动掌用户确认的叙事与用光设定)。
4. 未找到合适项目视频时，复用已有候选原帧或[查统一参考池](#多方向检索与复核)。将动作拆成能看见的短语：例如「掌心青蓝细丝收束」「两层空气环先后离手」「擦过人物只带风压」「岩壁碎石抛散」「洞口灰褐余尘沉降」。别只搜招式名，也别给每镜重复同一关键词。下方旧命令只用于内部排查或直接核对旧 ID。

```powershell
python -X utf8 .agents/skills/tx-layout-atmosphere/scripts/search_vfx_refs.py '山体级 青蓝掌形冲击 双层空气压缩 岩壁受光' --top 15
```

用 `--batch <UTF-8 查询文件>` 按动作阶段批查；需要沟通可加 `--html <新文件>` 生成可展开本地 GIF 的候选页。检索继续使用原库标注索引；命中后先读 `preview_gif` 快速看片，未缓存则看缩略图／原片。已核对的参考按 ID 复用，库或内网原片不可用时回退到已核对的项目参考或设计图。缩略图筛选后要开原片核对前后帧、记录原视频路径／ID 和时间；找不到对应阶段就不硬套。仅在用户要 UE 落地时另查模板，视效视频本身不证明工程资产可用。

其他程序可用 `--library <本机库目录>` 或 `--index <index.json>` 运行同一个脚本；只有 JSON 索引时使用内置文字检索，不依赖原检索程序。排序仅用于候选筛选，所有交付仍回原片核对。已有明确原片可跳过索引，直接用本地文件填写参考清单。

## 多方向检索与复核

1. **先写可见的动作。** 每镜按布局拆 2–8 条视觉方向，主动作放第一。比如吸食镜拆「红丝向心收束／红色流体材质／瞳孔近景／晶体环境／暗雾受光」。每条可写 1–2 组近义词，词组间用空格拆词；`require` 外层每组都要满足，内层任一词出现即可；只用明确反例填 `exclude`。晶体的透光、主招的吸聚分别判断，不用一个泛词给全镜排序。
2. **先合库，再按相关度筛。** 将可用索引统一为可搜索文字，用同一套词频权重打分；默认每组从整个候选池取 25 条，首屏最多 20 条。每个镜头方向内合并查询排名，先满足方向最低数，再给最多 3 个符合门槛、基准首屏和已登记曝光均未见、有本地 GIF 的候选，最后按镜头方向轮转补位。只按动作与特效层组织，无来源配额和轮转。某方向不足就列明缺口。相同源文件和人工确认的近重复族只选一条；并列用镜号和条目 ID 的固定散列，同输入与索引版本可复跑。
3. **看片，把取舍写出来。** `index.html` 只显示一份候选列表，`results.json`、`检索对照.csv` 记录统一编号、查询、排名、分数、命中、方向门槛、已知预览秒段和取舍。候选页、表格、正式板不展示来源库。抽看 GIF 后另存 `reviews.json`，例如 `{"ref_0123456789abcdef":{"status":"可借用","reason":"只借向心轨迹，不借金色"}}`。`不适合` 的条目重跑不进首屏，但保留证据；其余保持「待看片」。预览没有已核原片秒段时保留待核，不把文件名或 GIF 时长当成原片时间。交正式板前再开原片确认，在清单里填写 `ref_…` 编号、`source` 和实际秒段，按 [交付流程](pureref-vfx-board.md) 导出。外部链接单列，未确认素材可用性不进板。

从项目根目录运行；输出必须是新目录。复核版追加 `--reviews <复核文件>` 并另存输出目录：

```powershell
python -X utf8 .agents/skills/tx-layout-atmosphere/scripts/search_vfx_diverse.py <查询.json> --out <新目录>
```

```json
{
  "shot": "镜号",
  "baseline": ["能量 汇聚", "暗红 吞噬"],
  "seen_ids": [],
  "families": {},
  "routes": [
    {"id":"action","label":"向心抽丝","queries":["吸入 抽丝 聚拢"],"require":[["向心","吸入","聚拢"]],"exclude":["向四周爆开"],"min":3},
    {"id":"light","label":"暗雾内闪电","queries":["暗雾 红色 电弧"],"require":[["暗雾","黑烟"],["闪电","电弧"]],"min":2}
  ]
}
```

`baseline` 填原先会用的查询，仅用于内部比较和排除探索位已曝光条目；`seen_ids` 只填确有曝光记录的条目，`families` 用 `条目ID → 已核近重复组名`，既有的内部 ID 仍兼容。原 UE 库可用 `--library <本机库目录>`，仅有索引时用 `--index <index.json>`，缓存路径用 `--cache <GIF缓存目录>`。无缓存的条目保留记录，但不占探索位。

补充索引默认从 `E:\VFX_Reference_Library\GIF\` 的同级 `vfx_index.json` 读取，只收索引中预览文件实际存在的记录。别的电脑可用 `--gif-library <GIF目录>` 或环境变量 `TX_VFX_GIF_LIBRARY` 指定镜像位置；目录结构与同级索引一起保留。`--no-gif-library` 仅用于维护排查；`--internal-audit` 可另存索引健康和来源信息，不随用户交付。新增素材先更新对应索引，再重跑；搜索不改索引、原片、GIF 或已交 `.pur`。

## 传入出图与留痕

- 一般每镜 1–2 张原视频关键帧就够：`Layout / 现图 = 底图`、`项目设定 = 颜色和形态身份`、`视频关键帧 = 本镜指定层的质感和结构`。只迁移点名的结构、方向、疏密、折射、受光或粉尘；排除参考角色、机位、布景、字幕、水印、预览棋盘和不匹配的色彩。按原有出图规范保持原画幅、机位、姿势、遮挡和光源连续性。
- 纯反应不单独搜库、也不新增光效。仅在相邻镜头及当前帧支持时继承短促反光或局部扰动；命中后的镜头区分碎石、余尘和仍在发光的招式，别把峰值爆闪延续到余尘。
- 用户要先挑时，给候选编号、原视频或片段、截图、借用层与排除项，先标待确认。确认时仅登记该编号及适用层；需要修改则另存新版本，保留源视频和旧截图，未确认不改批准登记。出图验收另查：阶段正确、方向连续、特效没有改变画面锁定项、局部受光有来源。


## 使用创意参考库中的已选条目

- 用户给出 `TXREF-…` 或明确要查共享参考库时，从项目根目录运行 `python -X utf8 .agents/skills/creative-reference-search/scripts/reference.py lookup TXREF_ID --for-generation`。可先用 `find '镜号或标签'` 查 ID。只把返回的高清关键帧按已登记的借用层传给出图；仅收藏的链接、GIF 和未许可出图的条目不作为图像输入。正常镜头仍沿用上面的项目参考优先级，不自动拉取外网。
