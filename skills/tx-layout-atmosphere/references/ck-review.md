# 踏星｜出片审核页与美术一致性

适用于场景／特效 CK、正式镜头和返修版，与原生工具、外部模型、UE 或人工渲染无关。候选按顺序纵向连续排列，不在页顶逐张切换；每张卡各自放主图、画笔与编号、修改意见、通过／退回；分镜／Layout、设计依据和导入导出折叠。制作端先逐项做自检，把原始版本、成图哈希、basis、checks、evidence 写入候选 qa 对象；可核验的完整自检可直接放开审核按钮，未核或有阻断项则保留待补。审核人不重复填写制作检查表。页面保留旧记录，返修按新版本重新审核。

## 生成前：核对有没有已定设计

- 按本场实际空间、时段、破损状态和机位，查对应 Design、Shading、批准记录或用户最新指示。设计管构造、门窗、地标、道具与有意图的用光；Shading 管材质和造型，展示照明不自动成为镜头光。Layout 管机位、人物关系、可见范围，剧本管时段与事件阶段。
- 每个 CK 记下适用文件与版本，逐条写必须保留项：空间边界／入口／地标／道具；光源位置和来向、明暗比例与冷暖；材质、雾及前后层；角色／特效阶段。适用图应随简报传给工具；缺图时写实查范围，不把未查标为无设计。用户主动改动的项单列来源，不默默覆盖别的要求。
- 同时存在设计图与 Layout 事实冲突时，保存对照和冲突点，优先澄清实际制作口径；影响 CK 的冲突未解，不放行。

## 生成后：逐镜出审核页，不只交图墙

- 同编号并排放分镜截图、Layout 有效画面、成图；继续展示对应美术和明确的对照结论。联排里已有可核对的分镜，可以引用左栏并标明来源；没有对应截图时标「待补」，不拿邻镜冒充。
- 实际打开对照，逐项记录构图／画幅、场景内容／地标、光向／明暗、材质／雾、特效阶段／遮挡；明确「符合」「偏差待修」「接受偏离及依据」。不能靠一句「有电影感」或尺寸检查放行。门窗、主光、地标等有未解决偏差时保留待复核，先返修。
- 页面允许逐张打字、画笔、编号标记、撤销、按图层批注。通过／退回要生成记录，含候选号和版本、成图哈希、来源、核对项与依据、意见、归一化批注、时间。页面本机保存是草稿便利，不替代归档。
- 收到审核归档后，校验候选编号、版本和成图哈希，回填场次 CK 登记，并分别通过场景与特效；只批准单一张图不等于整场已放行。返修更换版本后不沿用旧通过。未收到记录时保持待确认。

## 退回后的返修闭环

1. 读取退回归档、画面标记和文字意见，对照同镜 Layout、分镜与当期美术，把“改什么／保留什么”写进返修简报。
2. **核对完必须实际出新版图。** 保留旧图与反馈；新图用新版本、不同文件名和真实哈希。生成未得到新版时标“待出图”，原候选保持退回；归档、简报和提示词都不是新版成图。
3. 对每个被退回的候选逐条拆出文字意见和编号／绘画批注，逐条对照成图标记“通过／未解决／待确认”，并写明画面依据。复检同时核对美术设计、Layout 和保留项。只要还有一条未解决，整张图只能标“待返修”；仅完成部分意见的中间稿可预览，但不得作为完整返修送审或通过。收齐本批所有退回件并逐张执行，不漏镜、不挑意见。
4. 刷新审核页，提供旧／新版与可追溯意见，重新送审。只接受对应新版及哈希的通过归档；退回再循环。
5. 本次任务范围内的必需 CK **全部通过并落档**才开始后续镜头；明确跳过的范围须留记录，与通过区分。

## 可复用页面

[模板目录](../assets/ck-review/)：复制 review.html、review.js 和对应图像到交付目录，旁边提供 review-data.js。设置 window.CK_EPISODE 为集号；window.CK_DATA 是列表，每项包含 id、version、sha256、source、t、size、file、layout、storyboard、art（可空）、artSource（可空）、artNote、note。无对应分镜时提供明确标「待补」的占位画面，审核依据必须登记实际缺项。打开页面可离线审核，不把素材发送到外部服务。
