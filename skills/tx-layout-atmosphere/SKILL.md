# 踏星｜Layout → CG 电影氛围图

出图任务默认每镜交付**一张可审的基础图**。所有执行程序先读 [镜头交付流程](references/workflow-contract.md)，共用取证、简报、构图锁、验收和交付；CK、正式出片和返修版本都交同一[审核页](references/ck-review.md)，不分工具或模型；制作端先自检，审核端只需提意见或通过／退回。只替换 [出图适配器](references/render-adapters.md)，不替换标准。参考查找任务按下方独立入口交付，不默认出图。

## 入口选择

- **整集／整场先定 CK**：按[场次 CK](references/workflow-contract.md#场次-ck先定标准再出图)为每场选代表全景，按用户需要做不同氛围／色调。涉及特效打斗另定特效标准镜。该场所需 CK 经用户通过并落档才进入后续出图；明确跳过 CK 则直出。纯单镜和局部返修不默认重开 CK。CK 交[审核页](references/ck-review.md)，先核设计证据和成图一致性，支持文字、绘画、标记以及通过／退回归档。

- **场次美学参考（独立模块）**：明确要场次特效美学、灯光／质感或创意参考图时，按[场次美学参考](references/aesthetic-reference.md)取证、写提示词、生成候选并移交。看 Layout 提炼意图但默认不垫灰模；即梦 V8.2 走官方画布 CLI。候选不是成片，用户选中后才把指定判断带回正式镜头。
- **Layout 出图／返修**：继续下面的镜头流程；有实质特效时先检索并核对原视频关键帧，选中的帧实际传入出图。纯表演和普通氛围镜不搜库。
- **按镜号或剧情找特效参考／出 `.pur`**：「3-6-69 找一些参考」这类请求也直接触发，无需用户点名格式。按叙事拆阶段、核对原片并按[统一交付规范](references/pureref-vfx-board.md)运行 `scripts/build_vfx_pur.py`。**必交独立动态 GIF、同批 GIF 内嵌的原生 PureRef 2.x `.pur`、原片出处与起止秒**。验 GIF 可播、`.pur` 脱离源素材仍能打开，才算交付完成。浏览页和静态图只是补充；明确只要链接或指定其他格式时按用户要求。缺 Layout 标「待补」；未要求出图不生成新成图。
- **特效参考检索**：需要从库里找候选时，按[多方向检索与复核](references/vfx-video-reference.md#多方向检索与复核)运行 `scripts/search_vfx_diverse.py`，把可用索引合为一个候选池，按镜头方向和相关度排序。候选页和正式交付都不分来源库；保留可追溯的原片与秒段。已知原片或 ID 可直接核对；候选页不等于正式参考板。

## 1. 锁定镜头与叙事时刻

- 镜头号可用 `3-2-5` 或 `Ep003_sc002_005`。有用户指定 Layout 时用它锁画面；只有镜头号时优先查单镜 Layout，查看实际内容，确认镜头、版本和动作阶段。动镜头可查邻镜，挑一帧最能体现本次要求；不把整集缩略图当出图参考。
- 先看对应 StoryBook 分镜和 Layout 原帧，必要时看前后镜。分镜与 Layout 的明暗块、逆光方向、天候、色温、雾尘和情绪提示是镜头用光的起点；白模或平光是占位，不是成片标准。剧本定稿管场次时段、叙事和动作因果；Layout 锁机位、景别、透视、姿态、主体占比和遮挡。用户指定的 UE 预览用于核对可见模型和空间，不照搬展示光。若定稿与 Layout 对关键时段或动作有实质冲突，先问一个聚焦问题，再生成。
- 默认锁定原图比例、有效画面四边与视场，按原画幅铺满画布，不加上下或左右黑边，不裁切、不拉伸；只有用户明确放开的项目才重设计。放开特效造型不等于放开机位，场景总览也不自动替换 Layout 的观察角度。

## 2. 场景先行，按可见内容找资产

**每个资产先查 Shading 图，缺图再用设计图（不借手绘画风）。** 场景、人物、怪物和道具都按各自的镜头版本查找：先看资产的 Shading 图，确认画面内容与本镜头需要的造型、服装、状态或材质匹配。有合适的 Shading 图就用它；找不到、打不开或版本不匹配时，只对该资产回退到设计图。因设计图多为手绘风格，直接套用会拉偏写实 CG 画风，**按用途只借可核实的造型／地标，或明确需要的光影层次与氛围；不借手绘笔触、展示光和参考机位**。Shading 图管资产外观和材质，Layout 仍管机位、景别、姿态与遮挡；Shading 图的展示光不直接当作镜头用光。用户明确指定的参考优先。

1. **场景与氛围**：从选中的场景参考中提取可识别的轮廓、地貌、开闭空间、材质、地标。先分析它与 Layout 的观察角度差：从 Layout 的镜头方向重排前中远景、透视与遮挡，明确哪些地标应看得见；不照搬资产参考图的机位。优先用清晰单图或设计板中的有效单格。
2. **人物、怪物与道具**：只找本帧可见、会影响画面的资产；确认镜头阶段的造型、服装、状态和道具。资产参考管身份、造型和材质，Layout 管姿势；不带入参考图中本镜头未出现的武器、动作或全身景别。
3. **电影用光与质感（默认必做）**：先明确观众先看哪里、这一拍应感到什么，再据分镜、Layout 和剧本时段布光。每镜写明可解释的主光来源/方向、明暗比、色温关系与空气层次；场景空镜也要有明暗重心。人物默认判断是否需要背光或侧逆轮廓光：优先让天光、窗、实景灯或已有发光体勾出迎光侧的发丝、肩线与剪影；主体靠受光面和暗面反差成立，必要时用弱反射仅托住眼神或手势。不画一圈发光描边，不为看清人物照平背景。用掠射光、粗糙度差、受光高光与接触阴影区分岩石、钢、皮革、织物；晶体用透射、厚薄吸收与局部亮边。允许按镜头有依据地补/减薄雾、浮尘、湿反射、风化细节或实景光，增强情绪和前中远景；不改机位、动作、时段或地标，不堆装饰和无来源的光效。
4. **最后定特效**：先问镜头要不要特效，再确认来源、颜色、形状、时序和与场景的相互作用。**踏星项目的特效设计必须合乎 UE（Niagara/Ribbon/Flipbook）工程制作逻辑：无论是气流、刀光、爆炸还是两人能力对峙，都必须具备清晰、流畅且富有美感的线条感展示（如动态 Ribbon 条带、气流引导弧线、锐利能量射线与清晰的受力轨迹），避免无结构、糊成一团的纯光斑或纯烟雾**（详见 [UE 特效线条感设计规整](references/ue-vfx-line-language.md)）。**需要重点探索时可建议「独立美学参考 → 锁 Layout 落地」；用户明确要求或确认后才启动独立探索。常规出图／返修按原任务继续，不因未选美学分支而暂停。**Layout 占位特效不代表定稿，用户明确要求自行设计时可重塑效果；不能据占位色认定技能。优先分清主角技能、环境二次反应和可见物理后果。项目已有独立特效设计流程时，仅明确需要设计、改效或制作拆解才联动；普通氛围图无需额外技术拆解。

按角色给每张参考标注用途与禁带内容，例如“机位/构图”“场景/材质”“角色/服装”“光线”“效果”。用户确认的版本优先；目录名 Final 或文件名不等于批准。关键构图、主资产、技能身份或光色存疑且会明显改变画面时，先把已查到的证据和两个可选方向问清楚；其他细节由执行者决定，不逐步请示。

### 按需调用真实特效视频参考

- 当出图这帧确有可见技能、命中或余波，默认按「招式／作用对象 + 当前动作阶段」走[真实特效视频参考](references/vfx-video-reference.md)，从同版本项目 UE 预览或库内原视频选帧，并把入选画面实际传给原生 GPT 图像工具。普通氛围、纯表演和已明确不搜库的镜头跳过；反应镜只继承有根据的局部受光或风压，余波镜只找余波。
- **Layout 锁机位与动作，项目设定定招式，视频只参考约定的效果层。** 同一事件共用颜色和衰减逻辑，但按蓄力、释放、擦身、命中、余尘分别选帧；只有近似素材时只借匹配层，没贴合素材就退回项目设计与可见证据。已出图按用户要求局部返修，不自动重做或升级候选审批状态。

### 已确认样板的迁移

- 本批已有用户认可的镜头时，把它标为「用光样板」，保留其成图，不无故重抽。**迁移视觉判断，不复制画面配方**：继承明确主光、暗面保留、受光轮廓、材质反差、空气透视和叙事焦点；不照搬样板的云缝、风雾、调色、人物、机位或额外元素。
- 批量先按场/时间连续性列主光方向、环境色与光源动机，再按每镜观察角度写「焦点 → 亮哪一块 → 哪一块压暗 → 什么材质/介质接光」。空镜让受光地标、暗部框景和远近层次讲故事；近景托一侧眼神或手；背影和动作镜优先让轮廓和肢体分开，不正面打平。强光束、火光和雾只在有来源、对这一拍有用时加。
- 分镜与 Layout 景别不同时，沿用 Layout 构图，只迁移分镜明确的情绪、光线和节拍；分镜镜号与内容对不上时，查邻镜和剧本，不凭号硬套。剧本「傍晚」与冷蓝 Layout 可用落日后蓝调时刻兼容；保留必要的微弱天际余光，不机械照搬成深夜或橙色夕照。确实影响情节且无共同解释时再确认。
- 高地雾从谷底到山腰、平台边缘分层，按地形和建筑遮挡绕流；双人表演区用同一实景光源连起两人受光面与脚下反射，周边压暗。风感靠一致方向的薄雾、发丝或衣角，不拿雾盖住脸、动作与主体轮廓。
- [Ep003_sc005_017 用光样板](references/taxing-project.md#已做镜头说明) 已获用户确认，用于校准本批电影用光质感，不作为各场的统一调色。

## 3. 生成、检查、交付

- 把 [镜头简报](references/workflow-contract.md#镜头简报与交接) 保存为 JSON，再按 [出图适配器](references/render-adapters.md) 运行。Codex 使用原生 GPT 图像工具；其他程序可选满足同样画幅、输入和锁定条件的工具。需要特效设计时补设计与验收，沿同一个出图步骤提交。无可用适配器时交可复做资料，明确待出图。
- 首版为写实度较高的 CG 电影氛围图，重点是可信材质、明确的光源、空间纵深与画面主次。见[首版风格与参考库](references/cinematic-look-standard.md)：实际传入一张合适的已通过样板，以成图验收质感，不堆固定画质词。
- 出图后打开实图对照 Layout：验四边、机位、主体位置/大小/姿态与资产；再验时段和分镜情绪、视觉焦点、主光来源、人物亮暗面及背光轮廓、材料能否分辨、远近层次。出现平光、人物吃进背景、整圈光边、材质糊成一片或靠全图提亮时先返修；同场锁时段与光源连续性，但按每镜视线重排受光、阴影和焦点。批量时已有认可样板就沿用，按镜头逐张生成并对照检查；发现个别镜头偏差只返修该镜，不覆盖已确认文件。
- 目视核对通过后，调用 `scripts/shot_delivery.py publish`。统一保存至 `output/` 的新版本 PNG，保留原始结果，等比全幅交 3840px 宽，复开核验并保存分辨率、适配器、人工对照结果与哈希。图像的内容一致性由实图检查判断，不由尺寸或哈希替代。
- 回复只给图、可点击路径、分辨率和最需要用户确认的一两个画面要点。首版方向通过后，按反馈一张张做局部精修，保留已确认内容；不自动扩写成多张变体。

在踏星本地项目找资料，或需要用现有镜头校准尺度时，读 [项目定位与样例](references/taxing-project.md)。
