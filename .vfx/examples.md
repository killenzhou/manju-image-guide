# 《踏星》调用示例与验收场景

在 TX 项目内自然描述需求即可；也可显式写 `$vfx-shot-design`。下述快捷写法是自然语言约定，并非额外注册的系统斜杠命令。

| 需求 | 应采用的行为 |
|---|---|
| 这张波动掌更漂亮，但 Niagara 和材质能做，人物和构图别动。 | Hybrid；提高轮廓、材质、层次，锁人物/机位，不靠海量随机粒子。 |
| Production，给制作执行；保留现有条带和 flipbook，也更漂亮一点。 | Production 显式优先；沿用已核对的资产约束。 |
| Concept，先探索黑雾的三种主轮廓，暂不考虑成本，背景别改。 | Concept；探索特效轮廓，仍锁背景，按要求给三种。 |
| 按 EP001 已批准的波动掌镜头统一这张，UE 可做。 | Style Match + 制作约束；先拿到指定镜头/时间码与批准证据，再观察比较。 |
| 参考这张新图统一波动掌，目前还没定稿。 | Style Match 待确认；候选预览，不把新图登记为已批准。 |
| Hybrid，做 3 秒寒冰释放，给首帧、爆发、尾帧设计，镜头别动。 | Hybrid；按 3 秒事件组织阶段，锁相机/身份/地标，给连续关键帧设计；未生成视频则注明。 |
| 这次不用特效规则，画一张自由创意海报。 | 不启用；普通创作，无强制 UE 拆解。 |
| 这张人像更漂亮，柔化光线。 | 不启用特效；普通局部图像修改，保留人物与结构。 |
| 这张特效更漂亮。 | 上下文确认为特效时 Hybrid，不因“漂亮”自动 Concept。 |
| Production，同时匹配这张经我确认的参考，别换机位。 | Production 主模式 + style_match 约束，不用参考构图覆盖当前机位。 |
| Concept，但也列一份可做拆解。 | Concept 主模式，附可做版本与差异；不擅自改成 Hybrid。 |
| 把镜头改俯视，只调整能量外轮廓，其他别动。 | 仅解锁用户要求的相机变化和特效轮廓，保留身份与场景结构；如重投影需补画则说明影响。 |

## 批准参考时记录
至少记录：id、镜头号、文件绝对路径、版本、时间码/帧范围、约束维度、批准人/用户确认原句与日期。缺信息先保持 candidate。新增明确批准项才进入 style-references.json 的 approved_references。

## 快速端到端检查（在项目下一次真实出图时）
1. 发送第一条需求并带底图；观察是否自然采用 Hybrid、保留结构并交真实图。
2. 发送人像或海报示例；观察不出现特效层表与制作流程。
3. 指定真实批准镜头后执行统一；对比色阶、纹理尺度、粒子密度与受光。
本次部署只验证配置、加载发现和规则审阅；以上真实出图验收没有在部署时自动消耗生成额度。
