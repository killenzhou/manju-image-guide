# 踏星特效工作台

## 打开编辑器

0. 用户要求打开踏星特效工作台时，调用 `mcp__tx_vfx_director__open_vfx_editor`。若本轮消息已经是工作台「直接出图」提交的 inline v2 请求，跳过打开编辑器，直接按下文生成；无需导出包、让用户再说明或再确认同一动作。保留源图机位、人物、姿态、文字及非特效区域。
1. 优先使用用户明确附加或指定的单张图片启动编辑器。
   - 当前消息有可访问的本地图片路径时，把它作为 `imagePath`；同一消息中的其他图片作为 `referenceImagePaths`。
   - 没有可访问路径时，仍直接打开空编辑器，让用户在界面内选择或粘贴源图。
2. 在调用 `open_vfx_editor` 前先观察源图，给出可编辑的对象建议，但不要替用户做不可逆决定。
   - `initialTargets` 可包含可见人物、武器、关键道具、天空、地面和重要场景区域。
   - 每个建议写清 `id`、`name`、`kind`、颜色、可选 `bounds`，并设置 `confirmed: false`、`source: "suggested"`，由用户在界面确认、改名或删除。
   - 用户明确说了“人物 A 火焰、人物 B 刀光”之类的独立效果时，预建 `initialEffectGroups`，每组只绑定相应 target id；不清楚时只建对象，不猜具体特效。
3. 调用 `open_vfx_editor`：
   - `imagePath`：用户明确选择的源图绝对路径；没有时省略。
   - `referenceImagePaths`：同一请求的参考图绝对路径；没有时省略。
   - `workspaceRoot`：当前工作区。
   - `effectHint`：用户同时给出的 VFX 意图。
   - `initialTargets` / `initialEffectGroups`：仅传递从画面和用户文字中有依据的建议。
4. 成功打开后停止操作。简洁模式中点技能即填入预设，单人无需建组或写说明。「手绘草稿」提供通用 20 种、踏星人物 10 种造型，可改贝塞尔锚点、整层移动缩放旋转或设置 2.5D Z 深度，可选导出透明 PNG，也可在手绘页点击「直接出图」把原镜头、手绘草稿和遮挡送到当前对话。原「引导与生成」的直接出图同样保留。未提交前不要自动出图。

## 执行 inline v2 请求

当消息包含 `VFX Director inline request` 且 JSON `schemaVersion` 为 `vfx-director-inline/v2` 时：

0. 若 mode 为 hand-draft-refine：第 1 张仍是唯一编辑底图；第 2 张是同画幅的合成草稿；第 3 张是手绘足迹；第 4 张是保护图；guides.draftAlphaImageNumber 指向独立透明特效草稿（通常第 5 张），不是文字层或普通参考图。使用可用的图片编辑工具按合成草稿精修并在对话展示图片：保留落点、路径、透视、近远与前后遮挡，只在足迹内改善材质和发光细节。第 4 张已扣除用户设为前景的笔迹区域；未标注区域保持原镜头。没有文字包装请求时，不要生成新文字或界面。不得要求用户导出工程或重新上传这次已经随请求附带的图。
1. 其他 inline v2 请求严格读取图片顺序。第 1 张是唯一需要保真的干净源图；第 2 张是标注引导图；第 3 张是影响区图；第 4 张是保护区图；如果 `guides.exactTextOverlayImageNumber` 存在，对应图片是透明精确文字包装层；其后才是编号参考图。
2. 按 `targets`、`effectGroups` 和每条 annotation 的 `groupId` / `targetId` 理解绑定关系：
   - 每个组只能影响其绑定对象与该组的区域、轨迹和参考图。
   - 不把人物 A 的火焰、人物 B 的刀光或环境雾混到其他对象。
   - 环形、弧形、螺旋和刀光拖尾使用 `geometry` 中的中心、半径、角度、方向、圈数、宽度和收束参数。
3. 遵循 `renderPlan`：
   - `single`：可见 VFX 组在一次编辑中完成。
   - `staged`：依次执行环境、各人物核心、次级拖尾/粒子；每一阶段保留已完成的人物身份、构图和前一阶段特效。
   - 文字包装始终是最后的确定性图层，不让生成模型重写中文。
4. 调用 Codex 内置 `image_gen` 编辑第 1 张源图。
   - 只加入可见 effectGroups 指定的 VFX。
   - 参考图只影响其 `roles` 和 `groupIds` 指定的职责与特效组。
   - 保持人物身份、面部、姿态、服装、场景几何、摄像机、构图、镜头原有文字和纵横比不变。
   - 禁止输出箭头、线框、编号、说明标注、选框、工具栏或任何 UI。
   - 精确文字包装层只作为后期叠加依据；生成干净 VFX 底图时不得仿写、改写或重画这些文字。
5. 检查结果。只有明显纵横比错误、人物身份严重漂移、特效串到错误对象或标注/UI 残留时，针对问题自动重试一次。
6. 在聊天中展示干净 VFX 结果，并说明使用了单次还是分阶段计划。若请求带精确文字层，提醒用户编辑器已导出透明文字层和 package JSON，可用于最终确定性合成；不要声称模型生成的文字是精确字层。

## 执行 inline v1 或 manifest

- `vfx-director-inline/v1` 继续按旧顺序处理：1=源图，2=标注，3=影响区，4=保护区，5 起为参考图。
- 当消息包含 `manifest.vfx-director.json` 路径或 Request ID 时，调用 `mcp__tx_vfx_director__get_vfx_request` 验证文件。
- v1 manifest 保持旧逻辑；v2 manifest 额外检查 targets、effectGroups、textLayers、renderPlan 和分组参考图。
- 保护区和影响区都是强语义提示，不承诺像素级硬遮罩。

## 边界

- 默认只生成一个单帧 VFX 方案；复杂请求按 renderPlan 分阶段，但不自行扩展成视频。
- 不把带 UI 的编辑器截图当作生成源。
- 未经用户提交编辑器，不执行出图。
- 文字包装层与说明标注不同：说明标注只帮助理解，精确文字层必须保持用户输入的字串、排版和样式参数。
